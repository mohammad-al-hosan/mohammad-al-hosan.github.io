UART Design Using Verilog for FPGA Implementation

A UART transmitter and receiver with parity checking, written in Verilog and tested on a CPLD/FPGA trainer board

Two Moore finite state machines, one for transmit and one for receive, frame each byte with a start bit, eight data bits, a parity bit and a stop bit. The design was written in Quartus II, checked in a Verilog testbench, and then stepped through bit by bit on an EPF10K10 board. Group project for EEE 304, Digital Electronics Laboratory, BUET.

Architecture

How it works

  • The transmitter loads a byte, then shifts it out serially between a start bit (0) and a stop bit (1).
  • The receiver detects the falling edge, re-checks the start bit at mid-bit, then samples each data bit once per bit period.
  • A parity bit equal to the XOR of the data bits is sent; the receiver recomputes it and raises an error flag on a mismatch.
  • CLKS_PER_BIT is a parameter, so the bit period is set at compile time without touching the state machines.

Key findings

  1. One state set serves both directionsTransmit and receive share the same six states, so the frame format is defined once and checked from both ends.
  2. The receiver re-checks the start bit at mid-bitIt samples the input through two flip-flops and confirms the line is still low halfway through the start bit, which rejects short glitches.
  3. A wrong parity bit is caught on hardwareAn all-ones frame with parity 1 set the error bit, which shows the check works end to end.

Note

This is a teaching-lab UART, not a verified IP core. Baud rate is fixed at compile time through CLKS_PER_BIT, and no runtime baud selection, FIFO, framing-error flag or full-duplex test was built. Simulation covers a single byte (0x2F); the board test steps through one pattern in each direction by LED, so no error-rate or baud-sweep data is claimed. My part: CPLD testing and interpretation of results, within a team of five.
